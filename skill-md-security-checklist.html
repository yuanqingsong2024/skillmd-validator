SKILL.md Security: 7 Risks to Check Before You Install a Skill

Piped remote scripts, destructive commands, wildcard tool approvals, hidden Unicode, and more — check these 7 risks before you install a third-party skill.

Published November 8, 2026. Rules checked against the official Agent Skills specification on 2026-10-23. Prefer the tool? Validate your SKILL.md free.

A SKILL.md file is not just documentation. When an agent loads it, the instructions inside can tell that agent to run shell commands, read files, and call tools on your machine. That is exactly why skills are powerful — and exactly why a skill you downloaded from someone else deserves a security check before you install it.

This checklist covers the 7 risks worth checking every time. Items 1–5 are patterns the free checker flags as warnings; items 6–7 need your own eyes, because no format check can catch intent written in plain language.

RISK 1

Piped remote scripts (curl … | bash)

The classic one. A skill that tells the agent to download a script from a URL and pipe it straight into a shell gives whoever controls that URL arbitrary code execution on your machine — and the URL's content can change after you reviewed it.

Check: search the file for curl, wget, and | bash / | sh. If a skill really needs a remote script, download it first, read it, and pin it to a version you reviewed.

RISK 2

Destructive commands

rm -rf, forced deletes, disk formatting, and recursive overwrites have no place in a skill you did not write yourself. Even a legitimate cleanup step can go wrong if a variable expands to an unexpected path.

Check: search for rm -rf, rm -r, mkfs, dd, and chmod -R 777. Ask whether the skill actually needs delete permission at all.

RISK 3

Wildcard allowed-tools

The allowed-tools frontmatter field pre-approves tools for the agent. A wildcard value hands the agent a blank cheque: every tool becomes available without further confirmation, including the dangerous ones from risks 1 and 2.

Check: if allowed-tools contains *, treat it as a red flag. A trustworthy skill lists exactly the tools it needs, nothing more. Note that this field is experimental and support varies by agent — never rely on it alone as a safety boundary.

RISK 4

Hidden Unicode characters

Invisible characters — zero-width spaces, bidirectional override marks, homoglyphs that look like ordinary letters — can hide instructions that you cannot see in a normal editor view but that an agent will still read.

Check: paste the file into the checker, which flags invisible Unicode. If you review by eye, use an editor that shows invisible characters, and be suspicious of any file whose rendered text and raw bytes do not match.

RISK 5

Over-broad file and network access

A skill that asks the agent to read your SSH keys, shell history, environment files, or password store, or to exfiltrate file contents to a remote endpoint, is asking for far more than most skills need.

Check: search for paths like .ssh, .env, .bash_history, and for upload or curl -d / POST patterns sending local data outward. A skill should only touch the files its stated job requires.

RISK 6

Instructions that contradict the skill's stated purpose

This one no checker can catch for you. A skill that claims to format Markdown but whose body also instructs the agent to "also send a copy of the conversation to an external address" is doing something its description never promised.

Check: read the body once, end to end, and ask: does every instruction serve the job in the description? Anything extra is grounds to stop and investigate.

RISK 7

A clean report is not a safety guarantee

A file can follow the specification perfectly, pass every format check, and still tell an agent to do something harmful in plain, readable language. Validation is a first pass, not a security audit.

Check: treat a zero-error report as "the format is fine, proceed to read it" — never as "this skill is safe." Always read a third-party skill in full before installing it, especially one that runs shell commands.

CHECKLIST

Checklist before you install a third-party skill

  • No curl | bash / wget | sh piped remote scripts
  • No rm -rf or other destructive commands
  • No wildcard * in allowed-tools
  • No hidden Unicode characters
  • No access to .ssh, .env, or other credentials, and no data sent outward
  • Every instruction in the body serves the job in the description
  • File passes the free checker with zero errors — and you read it in full anyway

FAQ

Does a clean validation mean a skill is safe?

No. A clean report means the format follows the spec and none of the checker's known risky patterns were found. It is a first pass, not a security audit — always read a third-party skill in full before installing it.

Can I check a file without uploading it?

Yes. The checker on skillmdvalidator.com runs entirely in your browser. Your file contents are never uploaded, analyzed, or stored; only anonymous page visits are counted.

What is the difference between an error and a warning in the checker?

Errors are the official specification rules. Warnings are security heuristics — worth a second look, but not spec violations. A file can have zero errors and still deserve rejection on a warning, or on your own reading of its instructions.
