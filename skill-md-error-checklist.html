SKILL.md Errors: Why Your Skill Won't Load (and How to Fix Each One)

The 9 most common SKILL.md errors — missing frontmatter, invalid name, folder-name mismatch, over-long description — with the exact fix for each.

The most frustrating thing about a broken SKILL.md is the silence. Most agents do not show you an error when a skill fails to load — they simply never surface it. That is why the first step is not guessing, but checking: paste the file into a checker and fix every error first, then work through the warnings. The nine errors below are the ones that actually stop a skill from loading, in the order worth checking them.

ERROR 1

No YAML frontmatter at all

What you see: the checker reports "No YAML frontmatter found", or the agent ignores the file entirely.

Why it happens: a SKILL.md must start with a YAML frontmatter block delimited by --- lines. A file that jumps straight into Markdown instructions has no name or description for the agent to read, so there is nothing to load.

Fix:

---
name: pdf-table-extractor
description: Extract tables from PDF files into CSV. Use when the user asks to pull structured data out of a PDF.
---

Your instructions go here.

ERROR 2

Unclosed frontmatter

What you see: "The opening --- has no closing --- line."

Why it happens: you wrote the opening --- and the fields, but forgot the second ---. Without it, the agent cannot tell where the frontmatter ends and the instructions begin, so the whole file is unreadable as a skill.

Fix: add a second --- line immediately after the last frontmatter field, before any instruction text.

ERROR 3

Missing or empty name

What you see: the checker reports that name is required.

Why it happens: name is the skill's identifier. Without it, the agent has nothing to register the skill under.

Fix: add one line, for example name: pdf-table-extractor.

ERROR 4

Invalid name characters or length

What you see: the name is flagged even though it is present.

Why it happens: the specification is strict here. A valid name is 1–64 characters, lowercase letters, numbers, and hyphens only. It must not start or end with a hyphen, and must not contain consecutive hyphens.

Fix — bad vs. good:

# Bad: uppercase, underscores, trailing hyphen
name: PDF_Table_Extractor-

# Good
name: pdf-table-extractor

ERROR 5

name does not match the folder name

What you see: the skill exists on disk but never appears in the agent — the quietest failure of all.

Why it happens: the specification says name must match the parent directory name. Rename the folder (or copy the file into a differently-named folder) and the agent can no longer reconcile the two.

Fix: pick one spelling and use it in both places. If the folder is pdf-table-extractor, the frontmatter must say exactly name: pdf-table-extractor. The checker verifies this whenever you fill in the folder name field — that field exists precisely for this check.

ERROR 6

Missing, empty, or over-long description

What you see: the skill is registered but never triggers, or the checker flags the description.

Why it happens: description is the trigger. Agents load every installed skill's name and description at startup and use the description to decide whether to activate the full skill. An empty description gives the agent nothing to match on; a description over 1,024 characters breaks the spec cap.

Fix — bad vs. good:

# Bad: empty, or a vague one-liner that matches nothing
description:

# Bad: a 1,500-character essay in the description field
# Good: what it does + when to use it, in one tight paragraph
description: Extract tables from PDF files into CSV. Use when the user asks to pull structured data out of a PDF, or when a PDF contains tabular data that needs to become a spreadsheet.

Keep it specific: name the file type, the output, and the trigger situation. The standing cost matters too — name + description sit in the agent's context for every session, so a bloated description taxes every conversation, not just this skill.

ERROR 7

compatibility over 500 characters

What you see: a spec error on a field you may have treated as free text.

Why it happens: compatibility is capped at 500 characters if provided. It is meant for short environment requirements — intended product, system packages, network access — not a full requirements document.

Fix: shorten it to a single line, for example compatibility: Requires Python 3.11 and network access to fetch PDFs. Move the rest into the body.

ERROR 8

allowed-tools written with commas

What you see: not a spec error, but a suggestion the checker raises — and one worth fixing anyway.

Why it happens: the spec defines allowed-tools as a space-separated string. Commas may be misread by some agents. Note also that this field is experimental and support varies by agent, so never rely on it alone as a safety boundary.

Fix — bad vs. good:

# Bad
allowed-tools: Read, Bash

# Good
allowed-tools: Read Bash

And never use a wildcard here: allowed-tools: Bash(*) pre-approves tools without per-use checks, which is a security warning, not just a formatting nit.

ERROR 9

Unknown frontmatter field (usually a typo)

What you see: the checker suggests an unknown field name.

Why it happens: usually a misspelling of a real field (descripton, allwed-tools) or a vendor-specific field another tool invented. Unknown fields are not spec errors, but a typo here means the field you thought you set was never set.

Fix: check the spelling against the six spec fields — name, description, license, compatibility, metadata, allowed-tools — and delete anything that is not one of them unless you know a specific agent reads it.

CHECKLIST

Before you publish: the 60-second checklist

  • File starts with ---, ends the frontmatter with a second ---
  • name is 1–64 characters, lowercase + numbers + hyphens, matches the folder name exactly
  • description is non-empty, under 1,024 characters, and says what the skill does and when to use it
  • compatibility, if present, is under 500 characters
  • allowed-tools, if present, is space-separated with no wildcard
  • File passes the free checker with zero errors — then read the warnings too, because a clean format report is not a safety audit

FAQ

FAQ

My skill passes the checker but still does not load. What now?

Check the install path first: each agent scans a different folder (Claude Code ~/.claude/skills/, Codex ~/.agents/skills/, Cursor ~/.cursor/skills/, Gemini CLI ~/.gemini/skills/ — the full table is on the checker homepage). Then restart the agent; most agents only scan for skills at startup.

Is an "unknown field" warning a spec error?

No. Errors are spec violations (missing or invalid name/description, unclosed frontmatter, folder-name mismatch, the 1,024- and 500-character caps). Warnings are security heuristics, and suggestions are best practice. Fix errors first, then warnings, then suggestions.

Does a zero-error report mean my skill is safe to install?

No — the same line the homepage draws. Zero errors means the format follows the spec and none of the checker's known risky patterns were found. A perfectly formatted skill can still tell an agent to do harmful things in plain language. Read third-party skills in full before installing them.
