SKILL.md Compatibility: Where Each Agent Looks for Your Skills

One SKILL.md folder, five different install paths. Where Claude Code, Codex, Cursor, Gemini CLI, and Copilot look for skills — and how to make one skill work everywhere.

Published November 15, 2026. Paths checked against public documentation and open-source installers on 2026-10-23. Prefer the tool? Validate your SKILL.md free.

Here is the good news: you only have to write a skill once. The SKILL.md format is shared, so the same folder works across agents. Here is the catch: every agent looks for that folder in a different place. A skill that loads perfectly in one agent and is invisible in another usually is not broken — it is just sitting in a folder the second agent never scans.

This guide covers the five agents most skill authors care about, the two locations each one scans, and the differences that actually matter.

ONE FOLDER

The one-folder trick

If you use more than one agent, do not maintain five copies of the same skill. Keep one canonical skills folder and symlink it into each agent's location, so a single SKILL.md serves every tool. One copy also means one place to fix: correct a description once, and every agent picks up the fix.

# Example: one canonical folder, linked into Claude Code's location
ln -s ~/.agents/skills/pdf-table-extractor ~/.claude/skills/pdf-table-extractor

DIFFERENCES

What actually differs between agents

1. The scan path — the difference that causes most "it works here, not there" reports. The format is the same; the folder is not. Before debugging anything else, check that the skill folder is under a path your agent actually scans.

2. User-wide vs. per-project. User-wide skills are available in every session. Per-project skills travel with the repository, so a teammate who clones the project gets the same skills. Put personal utilities user-wide; put project-specific workflows per-project.

3. The shared ~/.agents/skills/ location. Cursor, Gemini CLI, and Copilot also read this shared folder, and Codex uses it as its home. If you only want to maintain one extra location beyond each agent's own folder, this is the one with the widest coverage.

4. allowed-tools support varies. The frontmatter field that pre-approves tools is experimental, and agents differ in how much of it they honour. Never rely on it alone as a safety boundary, and never use a wildcard value — list only the specific tools the skill needs.

5. Unknown fields are ignored, not errors. The base specification defines six frontmatter fields: name, description, license, compatibility, metadata, and allowed-tools. Agents ignore fields they do not recognise, so a vendor-specific field will not break other agents — but a typo in a real field (descripton, allwed-tools) means the field you thought you set was never set.

DEBUG ORDER

Works in one agent but not another? Check in this order

  1. Path first. Is the folder under a location this agent scans? See the table above.
  2. Name match. Does the name field match the folder name exactly? A rename breaks this silently.
  3. Restart. Most agents read the skill list at startup. Restart the agent after adding or renaming a skill.
  4. Format. Paste the file into the checker and fix every error — a file with a spec error may load in a lenient agent and fail in a strict one.
  5. Trigger wording. If the skill loads but never activates, the description probably does not describe the situations it should trigger on. Add a "Use when…" sentence with specific keywords.

FAQ

FAQ

Do I need a different SKILL.md for each agent?

No. The format is shared. Write one skill, put it where each agent looks (or symlink one canonical folder into each location), and validate it once against the base specification.

Why does my skill work in Claude Code but not in Cursor?

Almost always the path, not the file. Cursor scans ~/.cursor/skills/ and the shared ~/.agents/skills/; a folder sitting only under ~/.claude/skills/ is invisible to it. Work through the five checks above in order.

Can I check a file without uploading it?

Yes. The checker on skillmdvalidator.com runs entirely in your browser. Your file contents are never uploaded, analyzed, or stored; only anonymous page visits are counted.

Does a clean validation mean a skill works in every agent?

No. A clean report means the format follows the spec and none of the checker's known risky patterns were found. It cannot verify your install path, your agent version, or whether the description triggers at the right moments — those are yours to check with the list above.
